# AXIOM ENTERPRISES

## Master Website Build & Acceptance Standard

**Applies to:** All websites designed, developed, rebuilt, maintained,
or deployed by Axiom Enterprises.

## 1. Purpose & Scope

This standard establishes the default minimum requirements for all Axiom
Enterprises websites. Each website must also have a project-specific
specification defining domain, purpose, audience, products/services,
conversion goal, branding, pages, functionality, commerce, content,
media, integrations, hosting, deployment, and legal requirements.

Project-specific requirements supplement this standard unless an
exception is explicitly approved.

## 2. Governing Rules

Every meaningful website element must do at least one useful job: 1.
Explain. 2. Establish trust. 3. Answer a question or objection. 4. Help
the visitor take an appropriate action.

If it serves no useful purpose, question why it exists. Do not
overengineer.

### No Guessing

If required information is unknown, FLAG IT. DO NOT INVENT IT.

Never fabricate testimonials, reviews, customer counts, statistics,
credentials, awards, partnerships, security claims, guarantees, dates,
registration numbers, contact information, pricing, ownership, or
licensing.

## 3. Pre-Project Information Gathering

Before substantive work begins, gather and verify the information and
access necessary for the project. Classify missing items as BLOCKING,
REQUIRED BEFORE LAUNCH, or NON-BLOCKING.

### Business Information

Collect where applicable: - Legal and operating business names -
Business description - Primary contact - Email, phone, and applicable
address - Registration information - Products, services, pricing -
Target customers and service area - Business hours - Domains/websites -
Branding, logos, marketing material - Required legal/policy information

### Social Media Inventory

For every business social-media account collect: - Platform -
Display/account name - Username/handle - Exact profile/platform URL -
Ownership/admin information - Account status - Required access level -
Whether appropriate access has been granted

Include Facebook, Instagram, LinkedIn, X, YouTube, TikTok, Pinterest,
Threads, Reddit, and other relevant platforms.

### Account Access & Password Security

Necessary authorized access must exist before work requiring an account
begins. - Prefer delegated/admin access where supported. - Passwords and
secrets must never be stored in this specification, source code, public
files, ordinary shared documents, spreadsheets, or GitHub. - Use an
approved password manager/secure credential system when credentials must
be retained. - Never commit passwords, API keys, tokens, recovery codes,
or authentication secrets. - Enable MFA where appropriate.

### Website & Platform Access Inventory

Identify required access to domain registrar, DNS, hosting, WordPress,
WooCommerce, GitHub, email, analytics, Google Search Console, Bing
Webmaster Tools, payment processors, CDN, backups, databases,
plugins/services, social platforms, and integrations.

### Digital Asset Inventory

Gather logos, brand guidelines, fonts, photographs, videos, existing
content, product media/descriptions, testimonials, reviews, documents,
downloads, advertising, and analytics. Verify ownership/licensing before
reuse.

### Existing Presence Review

Before rebuilding, review the current site, indexed pages, search
presence, social profiles, backlinks where relevant, analytics,
products, WooCommerce data, RSS, redirects, forms, and useful existing
assets. Do not destroy useful assets merely because a new site is being
built.

### Pre-Build Discovery Report

Record information received, accounts/platforms, URLs, access, assets,
missing items, questions, risks, preservation requirements, and
approvals.

## 4. Performance & Technical

-   Target LCP ≤ 2.5s, INP ≤ 200ms, CLS ≤ 0.1.
-   Fully responsive on phones, tablets, laptops, desktops.
-   No unintended horizontal scrolling.
-   HTTPS/SSL site-wide.
-   Clean semantic HTML and logical heading structure.
-   Optimize images with appropriate dimensions, compression, responsive
    delivery, WebP/AVIF where appropriate, and lazy loading below the
    fold.
-   Optimize fonts and prevent layout shifts.
-   Configure appropriate caching.
-   Minimize unnecessary CSS, JavaScript, libraries, and third-party
    scripts.
-   Provide uptime monitoring.
-   No known broken links, images, videos, forms, buttons, navigation,
    downloads, or checkout functions.
-   Provide a useful custom 404 page rather than blindly redirecting all
    404s.
-   Test Chrome, Edge, Safari, and Firefox.

## 5. Security & Reliability

-   Implement appropriate CSP, HSTS, X-Content-Type-Options,
    Referrer-Policy, and Permissions Policy where applicable.
-   Never expose secrets, database credentials, or payment credentials.
-   Keep dependencies minimal, maintained, and security-scanned.
-   Validate submitted information server-side where applicable.
-   Protect forms against spam and automated abuse.
-   Maintain backups and a documented restore procedure.
-   Monitor SSL validity where applicable.
-   Monitor critical form, checkout, payment, registration, and
    confirmation failures where practical.

## 6. SEO & Discoverability

-   Unique accurate title tags.
-   Useful meta descriptions.
-   Valid XML sitemap.
-   Correct robots.txt.
-   Truthful structured data/schema where appropriate.
-   Clean readable URLs.
-   Appropriate alt text.
-   Logical internal links.
-   Canonical URLs where needed.
-   Open Graph/social metadata.
-   Favicon/site icons.
-   Configure Google Search Console where applicable.
-   Configure Bing Webmaster Tools where applicable.
-   Verify production is not accidentally blocked by noindex,
    robots.txt, development settings, authentication, or incorrect
    canonicals.

## 7. RSS

Every Axiom website capable of publishing content must provide a
functioning RSS feed: - Standards-compliant - Public where appropriate -
Permanent feed URL - Correct title/description/content URLs -
Publication dates - Automatic inclusion of eligible new content - RSS
autodiscovery in HTML head - Production validation/testing - RSS
regression testing after updates

## 8. Accessibility

Target WCAG 2.2 Level AA: - Keyboard-accessible UI - Visible focus
states - Skip-to-main-content where appropriate - Adequate contrast -
Readable typography and line lengths - Accessible labels/instructions -
Accessible validation/errors - Appropriate touch targets - Logical
headings - Accessibility statement where appropriate

## 9. Content: WHO / WHAT / WHERE / WHEN / WHY

All meaningful content must answer these questions wherever relevant.

### WHO

Identify the website/brand, Axiom Enterprises, responsible
business/operator, author/creator where appropriate, and copyright
owner.

### WHAT

Clearly explain the product, service, listing, article, offer, event,
information, or customer deliverable.

### WHERE

Provide appropriate descriptive links to product/service pages,
purchase/checkout, contact, related content, sources, policies, next
steps, and relevant external destinations.

### WHEN

Provide accurate publication, last-updated, event, offer, deadline,
availability, and policy-effective dates wherever time matters. Never
fabricate dates to appear current.

### WHY

Make the purpose, benefit, and relevance understandable naturally.

Major pages/articles should remain understandable when reached directly
from search, RSS, social media, AI/search discovery, external links, or
bookmarks.

Before publishing verify WHO, WHAT, WHERE, WHEN, and WHY. If a relevant
answer is missing, FLAG IT.

## 10. Trust, Legal & Contact

-   Appropriate privacy policy.
-   Appropriate terms and conditions.
-   Primary Axiom Enterprises website contact email:
    **rise@empoweredathome.com**
-   Use this email for appropriate website contact, customer inquiries,
    pre-sale questions, support/contact links, and footer information
    unless explicitly approved otherwise.
-   Clearly identify the responsible business/operator.
-   Use cookie/consent controls where legally/technically required by
    actual practices.
-   Clearly state applicable refund/return/cancellation policies.
-   Display legitimate business verification where appropriate.
-   Never fabricate testimonials, reviews, customer stories, or
    endorsements.
-   Use trust/security badges only when genuine, current, authorized,
    and relevant.

## 12. Navigation & UX

-   Logical navigation appropriate to the site.
-   Consistent header/footer.
-   Clear visual hierarchy.
-   Visitors should quickly understand what the site is, what is
    offered, why it matters, and what to do next.
-   Add search only when justified.
-   Add breadcrumbs only when useful.
-   Important information must be easy to find.
-   Pop-ups must serve a purpose, be accessible, easy to dismiss, and
    not repeatedly harass visitors.
-   No dead ends.

## 13. Conversion & Business

Commercial pages must: - Clearly communicate value. - Clearly identify
the product/service and intended customer where appropriate. - Clearly
show price, currency, one-time/recurring status, and material additional
charges. - Explain exactly what the customer receives. - Provide an
obvious primary CTA with consistent wording. - Answer important
objections. - Use FAQs where justified. - Use genuine social proof
only. - Provide appropriate pre-sale contact. - Avoid competing
distractions. - Use no dark patterns or deceptive wording.

## 14. WooCommerce

Commerce websites must work with WooCommerce unless a project-specific
specification explicitly approves another platform. - Preserve
compatibility with supported WordPress/WooCommerce. - Products, cart,
checkout, accounts when enabled, confirmations, and transactional emails
must work. - WooCommerce pages must visually integrate with the site. -
Never modify WordPress/WooCommerce core files. - Use themes/child
themes, hooks, filters, APIs, and supported integrations. - Keep
product/customer/order data in appropriate commerce systems rather than
unnecessary custom duplication. - Avoid unnecessary payment-processor
lock-in. - Test product display, cart, checkout,
successful/failed/cancelled payment, duplicate submission protection,
confirmations, customer/admin emails, mobile, and desktop.

## 15. Checkout & Payment

-   Request only necessary information.
-   Use reputable secure payment processing.
-   Test successful, failed, declined, cancelled, and abandoned flows.
-   Prevent accidental duplicate transactions where practical.
-   Provide clear order confirmation and transactional email.
-   Provide a thank-you/success page and explain next steps.
-   Provide a contact fallback for payment failures.
-   Test mobile and desktop checkout.

## 16. Analytics & Measurement

-   Use privacy-conscious analytics.
-   Track meaningful CTA, checkout, purchase, contact, and other
    conversion events where applicable.
-   Minimize personal-data collection.
-   Analytics must not materially degrade performance.
-   Establish baseline conversion/performance metrics after launch.

## 17. GitHub, Development & Deployment

-   Each project must have an appropriate GitHub repository as master
    code repository/version history.
-   Use meaningful commits.
-   Protect production code from accidental destructive changes where
    practical.
-   Preview/test material changes before production.
-   Never use the live production site as the development playground.
-   Record approved hosting in the project-specific specification.
-   Document deployment, rollback, domain/DNS, SSL, and environment
    configuration.
-   Never store secrets in repository documentation.
-   Perform post-deployment critical-customer-journey testing.

## 18. Visual Media, Images & Video

### Media Opportunities

During design/development actively identify where custom photography,
images, illustrations, graphics, diagrams, animation, or video would
improve understanding, trust, demonstration, credibility, or conversion.

Do not add media merely to fill space.

### Media Recommendation

For every proposed asset specify: - Placement - Subject/content -
Purpose - Recommended dimensions - Aspect ratio - Format - Mobile
considerations - Whether custom-created, photographed, AI-generated, or
appropriately sourced

### Hero Media

Evaluate whether the hero works best with an image, photograph,
illustration, animation, video, or no media. Media must support rather
than compete with the primary message/CTA.

### Explanatory & Trust Media

Suggest useful visuals for workflows, benefits, examples,
product/service explanations, genuine credentials, publication
appearances, real customer/business imagery, and relevant brand/founder
credibility.

### Video Opportunities

Where useful, recommend founder introductions, offer explainers,
how-it-works videos, walkthroughs, demonstrations, and genuine
testimonial videos.

For every recommended video provide: - Purpose - Audience - Approximate
duration - Core message - Draft script/talking points - Required shots -
B-roll - Voiceover - On-screen text - Aspect ratio - Thumbnail concept -
Placement - Mobile considerations - CTA

### Image Production Brief

For recommended custom images provide: - Purpose - Subject -
Composition - Visual style - Orientation - Aspect ratio - Resolution -
Placement - Mobile crop considerations - Alt-text concept

### Production Prompts

For approved AI-generated imagery/video concepts, prepare
production-ready prompts for the appropriate creation tool. Maintain
website branding and Axiom visual identity. Final creative approval
remains with Goose and Sophia.

### Media Optimization

-   Appropriate dimensions/formats/compression
-   Responsive delivery
-   Lazy-load noncritical media
-   Appropriate video poster/thumbnail
-   Captions/transcripts where required
-   Never autoplay video with sound
-   Media must not destroy Core Web Vitals

### No Generic Filler

Avoid meaningless stock imagery such as fake business meetings, random
laptop pointing, unrelated skylines, or decorative AI robots unless
genuinely relevant.

Every visual must explain, demonstrate, establish credibility, answer a
question, or improve conversion.

### Media Opportunity Report

Before visual completion, produce an outstanding-media list stating: -
What is needed - Why - Placement - MUST / SHOULD / OPTIONAL -
Recommended production method

## 19. Media Ownership, Copyright & Watermarking

### Image Copyright Information

Every image must contain or have associated documented
copyright/ownership information according to Axiom Enterprises policy.

For every image record: - Copyright owner - Creator/source - Year -
License/usage rights - Asset/source-file reference

Never use an image without confirmed rights.

Where Axiom policy requires visible copyright information on the image
itself, incorporate the approved copyright identification without
unnecessarily damaging the image.

### AI-Generated Image Records

Document where appropriate: - AI-generation status - Tool/service -
Creation date - Ownership/usage-right information - Original production
asset/prompt reference where practical

Never falsely attribute AI-generated work to a human photographer.

### Video Watermark Required

Every video produced for an Axiom Enterprises website must contain the
approved Axiom Enterprises watermark/logo unless an explicitly approved
project exception exists.

Requirements: - Approved Axiom watermark - Consistent placement/sizing -
Visible without obstructing important content - Account for
aspect-ratio/mobile crops - Avoid platform-UI obstruction

### Video Copyright Records

Document: - Copyright owner - Production date/year - Creator/production
source - Music/audio licensing - Stock-footage licensing - AI-generated
asset information where applicable - Third-party usage rights

### Master Media Asset Register

Maintain ownership, copyright, license, source, and production
information for significant images, videos, audio, and media assets.

### No Unverified Media

If ownership or usage rights cannot be established, FLAG THE ASSET and
do not publish it until rights are verified or an approved replacement
is provided.

## 20. Final Acceptance Testing

Before a site is considered complete, test the full relevant
visitor/customer journey, for example:

**Visit/Search → Landing Page → Understand Offer → Establish Trust →
Answer Questions → CTA → Checkout/Contact → Confirmation → Next Steps**

Test appropriate combinations of: - iPhone - Android - Tablet -
Windows - Mac - Chrome - Edge - Safari - Firefox

Also verify: - HTTPS - Forms - Links - RSS - WooCommerce where
applicable - Payments where applicable - Email confirmations -
Accessibility essentials - SEO/indexing essentials - Media copyright
records - Video watermarking - Analytics/conversion events - Backups -
Rollback capability

## 21. Codex Working Instructions

Before adding a feature ask: 1. Does it explain? 2. Does it establish
trust? 3. Does it answer a question/objection? 4. Does it help the
visitor take an appropriate action?

If NO to all four, do not add it without explicit approval.

Do not overengineer.

Do not turn a focused website into a generic corporate website.

Do not add common features merely because they are common.

When factual business information, pricing, legal wording, testimonials,
credentials, photographs, payment details, account information, media
rights, or other source material is missing:

**FLAG IT. DO NOT INVENT IT.**

When an image or video would materially improve the site:

**FLAG THE OPPORTUNITY AND PROVIDE A PRODUCTION BRIEF.**

Classify requirements/recommendations where useful as: - MUST - SHOULD -
OPTIONAL

The objective is to build the simplest, strongest, fastest, most
trustworthy website necessary to accomplish the project's defined
purpose.
